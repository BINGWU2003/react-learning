这个示例用 `queryKey` 区分不同学习方向的缓存，并通过 `staleTime` 设置十秒的新鲜期。浏览器会向 Astro API Endpoint 发出真实 HTTP 请求；部署到 Netlify 后，该 Endpoint 由 Netlify Function 运行。

新增资料由 Mutation 完成。请求成功后不手动修改列表，而是调用 `invalidateQueries` 让所有列表缓存失效，由查询重新同步服务端数据。

## 观察重点

- `isPending` 表示当前还没有可展示的数据，`isFetching` 表示查询函数正在运行，包含后台更新。
- 查询参数必须进入 `queryKey`，否则不同筛选条件可能错误地共享同一份缓存。
- `queryFn` 接收 TanStack Query 提供的 `AbortSignal`，过期请求可以被及时取消。
- API Route 设置 `prerender = false`，只有该路由按需执行，Starlight 文档继续静态生成。
- Demo 数据只保存在 Function 进程内存中，重启、冷启动或切换实例后可能恢复初始状态；正式数据应使用持久化存储。
